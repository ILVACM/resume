# strategy.md — 简历编写与投递策略

> **定位**：简历**实例**（`Resume-{目标}.md`，区别于母版 `Resume.md`）的全部操作流程、方法与台账的唯一权威文档。
> **分工**：母版维护走 `AGENTS.md` §3.1 / §3.3；本文件管「从模板复制到投递打 tag」的实例全流程。

## 1. 定制投递流程（实例全流程）

1. **选取目标**：从 [`TargetCompanies.md`](TargetCompanies.md) 按公司性质分组选取目标公司。
2. **复制模板**：复制 `Resume-Lite.md`，重命名为 `Resume-{目标}.md`（如 `Resume-ByteDance.md`）。禁止直接改动模板。
3. **填充内容**：基于母版 `Resume.md` 的内容替换骨架条目，按目标岗位裁剪详略（实例内容偏离母版属定制的意义，结构基准仍源自模板）。
4. **构建 PDF**：`bash _temp/scripts/build-pdf.sh Resume-{目标}.md _output/Resume-{目标}.pdf`，输出至 `_output/`。
5. **登记实例**：立即在 §2 台账登记（只记 md 源文件，PDF 产物不入账），提交 `build(resume): 生成 XX 投递版 PDF`。
6. **投递打 tag**：每次实际投递前**必须**打投递快照 tag 并在 §3 台账登记（格式与细则见该节）。

## 3. 投递 tag 规范与台账

"哪版投了哪家"在此永久可追溯。

**格式**

| 类型 | 格式 | 示例 |
|---|---|---|
| 基线 | `v{版本}-base` | `v1.0-base` |
| 投递快照 | `v{版本}-{目标}-{YYYYMMDD}` | `v1.1-ByteDance-20260905` |

**细则**

- 母版达到稳定状态时打基线 tag；每次实际投递前**必须**打投递快照 tag，并在下方台账登记一行。
- 版本号：结构或重大内容变更递增次版本（`v1.0` → `v1.1`），仅错字润色沿用当前版本。
- 同一目标多次投递，日期不同即新建 tag，不覆盖旧 tag。
- Tag 创建后不删除、不改名。
