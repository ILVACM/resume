# strategy.md — 简历编写与投递策略

> **定位**：简历**实例**（`Resume-{目标}-{版本}-base.md`，区别于母版 `Resume.md`）的定制操作流程与实例构建方案的唯一权威文档。
> **分工**：母版维护走 `AGENTS.md` §4.1；实例登记见 [`INDEX.md`](INDEX.md) §2；投递 tag 规范见 [`tag.md`](tag.md)，日志见 [`TargetCompanies.md`](TargetCompanies.md)。

## 定制投递流程（两阶段，且相对独立）

> **实例构建**与**投递快照**是两个相对独立的阶段：构建产出可投的实例版本；投递快照基于任一已构建的 `active` 实例执行——可重复、构建后不投也合法、投递无需重新构建。

### 阶段 A：实例构建（产出一个可投版本）

1. **选取目标**：从 [`TargetCompanies.md`](TargetCompanies.md) 按公司性质分组选取目标公司。目标公司名称与清单不一致时，先按主营业务模糊匹配分组；无法匹配则停止并报告。
2. **复制模板并命名**：复制 `Resume-Lite.md`，重命名为 `Resume-{目标}-{版本}-base.md`（如 `Resume-金融科技-v1.0-base.md`）——**构建时就确定版本号并命名好**，`-base` 尾缀标识这是实例本体。禁止直接改动模板。补充规则：
    - `{目标}` 由用户提示词指定（**分组名或公司名均可**），须与后续所用构建方案对应；实例 md 落盘于**仓库根目录**（与母版/Lite 同层，非 `docs/`）。
    - 版本号：**首个实例独立起算 `v1.0`**（不关联母版基线 tag 版本）；内容实质修改升次版本（`v1.0` → `v1.1`），仅错字润色沿用当前版本。
    - 本复制重命名属实例构建/投递常规动作，免 LOG 登记，由 INDEX §2 台账 + commit 追溯。
3. **填充内容**：基于母版 `Resume.md` 的内容填充实例：**将所选方案的示范条目（3–4 个，按清单顺序）插入「重要经历」章节下**；求职意向、相关知识技能等既有章节按下方补充规则处理（实例内容偏离母版属定制的意义，结构基准源自模板）。补充规则：
    - 选择键统一为「适用领域分组」——同分组内的岗位差异，由方案内要点字段的分支选择承担；TargetCompanies「关注岗位」为空时以分组为准。
    - 实例「求职意向」（Lite 模板占位）**沿用母版求职意向原文**（`Resume.md`「求职意向」），除非方案或用户提示词另行指定。
    - **母版为事实源（里子），方案示范为定稿呈现（面板）**，Agent 仅做复制拼接与受控适配——对应分组的方案空缺时，**停止并报告，禁止回退母版自由手裁**。
4. **构建 PDF**：`bash _temp/scripts/build-pdf.sh Resume-{目标}-{版本}-base.md _output/Resume-{目标}-{版本}-base.pdf`，输出至 `_output/`。前置条件与兜底：
    - **字数闸门（构建前）**：脚本自动统计实例去空白字符数（口径见字数预算表）并与上限 **2200** 比对，超限以退出码 **2** 拦截、**不生成 PDF**；达上限 90% 以上打印预警。可用环境变量 `RESUME_MAX_CHARS` 临时覆盖（`=0` 表示关闭）；母版 `Resume.md` 与模板 `Resume-Lite.md` 自动豁免。
    - 脚本依赖 **Edge 151.0.4129.107**（绝对路径硬编码于脚本内）、managed Python 与 Git Bash `cygpath`——环境不符时**停止并报告**，不得降级尝试其他版本或工具。
    - **页数兜底（构建后）**：`pdf-check.py --max-pages 2` 校验真实页数，超页报 `[ERROR]`。字数闸门或页数兜底任一触发，均属预算失效的异常情况——**停止并报告人工**，由人工决定裁剪，不自动截断。
5. **登记实例**：立即在 [`INDEX.md`](INDEX.md) §2 台账登记（只记 md 源文件，PDF 产物不入账，状态 `active`），提交 `build(resume): 生成 {目标指向} v{版本} 实例 PDF`（"目标指向"即实例文件名中的 `{目标}` 值；base 实例 PDF 与阶段 B 的投递副本 PDF 是两种产物，勿混称"投递版"）。

### 阶段 B：投递快照（基于已有实例的一次投递）

前提：存在任一 `active` 状态的实例（刚构建的，或历史构建的——**无需重新构建**）。

1. **选取实例版本**：从 `INDEX.md` §2 的 `active` 实例中选定本次投递所用的文件；如需内容调整，先回阶段 A 迭代出新版本（新版本 = 新的 `-{版本}-base` 文件）。
2. **生成投递副本**：将所选 `Resume-{目标}-{版本}-base.md` 复制一份，尾缀 `-base` 改为 `-{投递公司名称}-{YYYYMMDD}`，得到 `Resume-{目标}-{版本}-{投递公司名称}-{YYYYMMDD}.md`（如 `Resume-金融科技-v1.0-招银网络-20260910.md`）——**文件名即投递记录**，实际投出的就是这份副本（PDF 按同名构建：`bash _temp/scripts/build-pdf.sh Resume-{目标}-{版本}-{投递公司名称}-{YYYYMMDD}.md _output/Resume-{目标}-{版本}-{投递公司名称}-{YYYYMMDD}.pdf`，沿用阶段 A 同脚本与环境前置（同含字数闸门，超限即 `exit 2` 拦截；超 2 页按阶段 A 兜底停止报告人工）。本复制重命名属实例构建/投递常规动作，免 LOG 登记，由 INDEX §2 台账 + commit 追溯。
3. **打投递快照 tag**：`git tag v{版本}-{投递公司名称}-{YYYYMMDD}`——与投递副本文件名的版本 / 公司 / 日期三要素一致；格式与铁律见 [`tag.md`](tag.md)。
4. **记录投递日志**：在 [`TargetCompanies.md`](TargetCompanies.md) 的投递日志追加一行（日期 / 简历文件 / 目标公司 / 对应 tag），其中「简历文件」填**投递副本文件名**、「对应 tag」填本次快照 tag（同日同公司多次投递的 `-N` 后缀规则见 [`tag.md`](tag.md)）；不覆盖旧记录。
5. **更新状态**：公司清单中该公司的「投递简历 / 状态」列更新为最新进展（`投递中` / `一面` / `二面` / `offer` / `挂`），「投递简历」填投递副本文件名；`INDEX.md` §2 该实例的「对应 tag」列更新为**最新一次**投递的 tag。
6. **提交落盘**：按 AGENTS.md §5.2 默认提交改动（`build(resume)` 类型，subject 含公司名与日期）；提交失败须明确上报。本次提交统一覆盖投递副本、INDEX §2 与 TargetCompanies 状态等全部关联改动。

## 实例构建方案设计

> **方案库定位**：为不同目标类型提供**确定性生成规格**——构建实例（阶段 A 第 3 步）时，按目标公司所属分组匹配对应方案执行。  
> 方案按 [`TargetCompanies.md`](TargetCompanies.md) 的公司性质分组组织；项目的取舍依据是 [`INDEX.md`](INDEX.md) §1「相关领域」。  
> **确定性验收标准**：条件不变（母版、模板、目标公司、LLM 模型、Agent 软件、操作模式均不变）时，依据方案生成实例，**无论执行多少次，产出结果都相同**——方案内禁止"酌情 / 参考 / 适当 / 视情况"类模糊表述。  
> **PDF 约束**：任何实例生成的 PDF 不超过 2 页。机制化保证：`build-pdf.sh` 在 MD→HTML 前执行**字数闸门**（口径见字数预算表，上限 **2200**），超限即以 `exit 2` 拦截、不生成 PDF；`pdf-check.py --max-pages 2` 作页数兜底。母版 `Resume.md` 与模板 `Resume-Lite.md` 自动豁免该闸门。上限由 2026-09-11 标定实验锁定（实测 2239 仍为 2 页 / 2280 已为 3 页），见下方字数预算。

### 方案选择指引（阶段 A 第 3 步的执行流程）

**输入**：目标公司信息 + 用户提示词要求 + 第 2 步复制出的实例副本

1. **选定方案**：依据目标公司所属的「适用领域分组」匹配方案（一分组一方案，选择键唯一）。`{目标}` 键由用户提示词决定（分组名或公司名均可），但构建方案的选择始终依据目标所属的「适用领域分组」。
2. **选定示范分支**：对照方案内「要点字段」的选取依据，按目标公司的具体情况命中对应示范。**分支判定输入仅限 [`TargetCompanies.md`](TargetCompanies.md) 该公司行已填写的「关注岗位 / 主营业务 / 其他备注」字段，做字面匹配**；字段为空或匹配不上任何分支关键词时，命中方案内默认分支（见「示范粒度」定义），**禁止依据外部信息或主观推断补出岗位画像**。
3. **内容构建**：将选中示范复制拼接进实例副本。
4. **自适应调整**：对照「要点字段」将拼接内容与目标公司实际情况对齐（受控适配——调整范围以要点字段所示为界，不做要点之外的自由发挥）。

**输出**：符合要求的简历实例（进入第 4 步构建 PDF）。

确定性边界：自适应调整的规则由要点字段封闭——目标公司不变时，调整的对象、范围、依据均不变，结果仍可复现。

### 方案条目结构约定

每个方案（一个小节）含 2 个字段——方案只展示关键要点与定稿示范，简历只是面板，关键还是里子（由黄泊凯人工把关）：

| 字段 | 含义 |
|---|---|
| 适用领域分组 | 对应 TargetCompanies 的公司性质分组，是方案的选择键 |
| 关键优势项目 | 有序入选清单（清单顺序即实例中的排列顺序），每项含"要点 + 示范内容" |

**要点字段的三重职责**（构成"示范选择与调整指令"，不构成"内容创作指令"）：

1. **选取理由说明**——为何该项目入选该分组方案；
2. **分支选择指令**——各示范的适用情形，Agent 依据目标公司具体情况选择对应示范；
3. **构建调整参照**——内容构建时对照要点将拼接内容与目标公司实际情况对齐（受控适配）。

**示范粒度**：单个项目的完整简历条目（从项目标题到要点 bullets 的整段 markdown）。同一方案内可含**多个示范**，对应同领域下不同类型的公司，由要点字段的选取依据区分。**默认分支**：方案内不显式带「分支：」后缀的示范（通常为关键项目1）即为默认分支；目标公司相关字段为空或无法命中任何分支关键词时，一律命中默认分支，禁止引入 TargetCompanies 未记录的岗位假设。

**字数预算（硬性上限）**：

| 项目 | 预算 |
|---|---|
| 实例全文（去空白，硬性上限，标定锁定值） | ≤ **2200** 字符 |
| Lite 模板固有结构（标题/基本信息/教育/技能/重要经历头，去空白实测） | 578 字符（实测锁定，随 Lite 修订重测） |
| 计入预算的单项目示范条目 | 200–**380** 字符 |
| 入选关键优势项目数 | 3–4 个 |
| 竞赛佐证短列表（不计入单条，计入全文） | ≈ 60–80 字符 |

> **计数口径**：去空白字符数 = 去掉全部空白字符后的**字符（码点）数**，canonical 实现为 `len(''.join(text.split()))`（`build-pdf.sh` 闸门即用此实现，经 `$PYTHON` 调用、不依赖 PATH）。**不得使用 `tr -d '[:space:]' | wc -m`**——本机 `wc -m` 按**字节**计（中文 1 字 = 3），会得到约 1.85 倍偏大的数值。计数**含 markdown 标记**（`#`、`**` 等，占比极小），与闸门保持一致，禁止另行剥离。

依据：母版单项目条目 716–1559 字符、全文 **9127** 字符（去空白口径，2026-09-11 复测；含空白约 1.1 万，随母版修订重测）。**2 页上限由标定实验实测锁定**：在同一版式下逐份构建测试稿，去空白 **2239 仍为 2 页、2280 已为 3 页**，故取锁定值 **2200**（floor 到 50，留余量 39）；两种独立构造（加长合并块 / 真实整块拼接）给出同一区间。压缩比 ≈ 2200/9127 ≈ 1/4。四档结构算式（Lite 固有 578、单条上限 380、佐证 80）：
- 4 完整项目档（企业服务 / 政企信息化，无佐证）= 578 + 4×380 = **2098**
- 4 完整项目 + 佐证档（理论最坏，无实际分组）= 578 + 4×380 + 80 = **2178**
- 3 完整项目 + 佐证档（共 7 组）= 578 + 3×380 + 80 = **1798**
- 3 完整项目档（软件外包，无佐证）= 578 + 3×380 = **1718**

四档均 ≤ 2200；现有 10 组实际体量 1304–1769，最大者（企业服务）距上限余量 **431**。超限属预算失效的异常情况——**停止并报告人工**，不自动截断。

注：「相关知识技能」章节**不做分组差异化**——各实例直接沿用从 `Resume-Lite.md` 复制的内容。另：清单尾部的「竞赛佐证」条目为**简短列表格式**（区别于项目示范的完整条目格式），用于汇总赛事背书，不计入单项目字数预算。　字数计数口径与闸门实现见上表注（码点计数、含 markdown 标记）。
