## 适用领域分组

AI / 大模型

## 方案构建意图简述

① 大模型方向招人，最看重能不能把模型真正用到工程里，而非只会调现成接口。
② 本方案以「省基金多智能体科研 + 测绘院本地化 RAG 全链路 + 光点大模型服务化拆分 + 智慧物流系统工程底座 + Agent 规约体系构想设计」五条为骨架：前三条证科研深度、端到端工程化、服务化与调度设计；第四条证承接 AI 落地的系统工程底座，末条证面向 Agent 的工程化思考。
③ 相比同届，形成能写科研、能落地交付、懂 Agent 治理的组合。

## 关键优势项目

- 关键项目1：
    需要突出的要点有：`多模态大模型 + RAG + Multi-Agent 直接对口大模型算法与应用岗——科研经历体现研究深度（文献调研/基金申请书撰写），分支：算法研究岗看科研深度，应用岗看 RAG 架构验证与数据流水线工程化`  
    示范内容如下：
```markdown
#### 广东省自然科学基金2026（面上） | 核心算法开发成员 | 2025.06 - 至今

**项目概述**：《模态缺失下的轻量化诊疗报告生成研究》（编号 2026A1515010964），依托中山大学肿瘤防治中心 600+ 例多模态私有数据集，研究"补全-验证-轻量化"技术链。

**核心工作**：
- 参与 Multi-Agent 系统工程架构设计与验证，实现智能体串行/并行调度逻辑
- 接入 RAG 外挂临床指南知识库，验证"诊断-验证-仲裁"闭环机制抑制医学幻觉的工程可行性
- 独立负责 GPU 服务器环境（Docker/Conda）与 600+ 例数据集清洗、脱敏、ROI 裁剪的标准化流水线

**成果**：完成多模态特征编码与多时序轻量化模型基础代码搭建；协助完成基金申请书核心内容撰写。
```

- 关键项目2：
    需要突出的要点有：`RAG 全链路工程化落地（意图路由/多路召回/Reranker/量化评估）且本地化部署——RAG 应用岗与知识库产品岗直接对口；分支：政企背景公司同时体现"数据不出域"合规能力`  
    示范内容如下：
```markdown
#### 广东省国土资源测绘院 | 系统开发实习生（卫星应用中心） | 2025.07 - 2025.10

**项目概述**：GDCORS 智能知识库与政企本地化 RAG 问答系统，面向 PB 级地理空间业务数据与海量专业文档，满足政企数据"不出域"合规要求。

**核心工作**：
- 采用「逻辑核心 + 功能插件」微内核架构（逻辑核心调度，插件标准接口挂载向量库/模型/意图识别），检索环节可独立替换
- 配套六层分层（基础硬件→数据采集→逻辑核心→插件支持→服务集成→应用交互），满足数据不出域
- 以 BERT 微调做意图二分类路由：内部查询走本地库、外部经安全通道受控访问，实现数据隔离分流与三级权限治理
- 构建 LLM-as-a-Judge 量化评估体系（相关性/准确性/幻觉率）反哺迭代

**成果**：专业问答忠实度≥95%/相关率≥90%；基于 vLLM 本地化部署 Qwen3，内网稳定运行。
```

- 关键项目3：
    需要突出的要点有：`LLM 微服务化 + 混合推理调度（本地 vLLM + 云端 API）+ 异步编排——AI 工程化应用岗直接对口；分支：AI 应用开发岗看微服务解耦与调度策略设计`  
    示范内容如下：
```markdown
#### 广州光点信息科技股份有限公司 | Python 开发实习生（AI 研发组） | 2025.03 - 2025.06

**项目概述**：全媒体热点追踪与 AI 自动化短视频生成矩阵系统。

**核心工作**：
- 基于 FastAPI 将大模型能力剥离为独立微服务（要点提取/脚本二创），业务与模型迭代解耦
- 本地 vLLM 部署 Qwen2.5-14B 与 Llama 3 承载常规提取，复杂创意路由云端 API——本质是成本/时延/质量的三角权衡
- 引入 Celery + Redis 异步队列，与下游数字人合成系统以 JSON 协议交接脚本/时间轴/素材

**成果**：单条热点到视频产出从人工数小时压缩至 15 分钟内。
```

- 关键项目4：
    需要突出的要点有：`工程底层基础——传统系统平台工程的完整落地经验（架构分层演进 / IoT 硬件底座 / 云边监控与 DevOps），是 AI 与 Agent 能力在真实业务中落地的前置条件；分支：AI 应用岗看"除模型外还能独立扛传统系统平台开发"，架构岗看"分层演进与通信中枢契约设计"`  
    示范内容如下：
```markdown
#### 机场物流集团 | 智慧物流系统迭代一期/二期 | 项目总负责人（二期） | 2024.09 - 2026.09

**项目概述**：校企合作两期交付的传统系统平台工程，是 AI 能力落地的工程底座。

**核心工作**：
- 独立主导二期全生命周期：业务调研、合同拟定、架构设计到验收交付
- 平台架构三段式演进：传统 Spring Boot 分层 → 按业务 SOP 纵向业务分层 → 以通信中枢为中心的星形（Hub-Spoke）拓扑，各组件只对中枢建立单一契约
- 一期工程底座：独立完成安检机硬件组装与负载校验，攻克专有协议实现高并发视频流解码；Docker 化 B/S 部署 + Prometheus+Grafana 云边监控（15+ 告警），P1 恢复 <5 分钟、可用性 99.5%
```

- 关键项目5：
    需要突出的要点有：`Agent 规约体系构想设计（三层架构 + AGENTS.md/.spec/ 双载体、27 项机制、锚点 ↔ Git 提交双向绑定、七项全局校验）——体现面向 Agent 的工程化思考与设计能力；分支：AI 工程化岗看规约体系设计，架构岗看约束层↔实例层分层`  
    示范内容如下：
```markdown
#### Agent 规约体系构想设计 | 个人思考实践 | 2026.08 - 至今

**项目概述**：由"直接向 agent 下达任务不可靠、其产出依赖无歧义引导"这一观察出发，构想并设计面向多 Agent 协作的工程规约体系（提示词工程 → harness 中间态）：人主导设计验收，规约约束 agent 交付。

**核心工作**：
- 三层逻辑（约束/知识/实例层）设计为 AGENTS.md 与 .spec/ 双载体，含 27 项机制与七项全局校验
- 任务锚点三层追踪；Git 提交以锚点打桩，实现锚点 ↔ commit 双向绑定
- harness 化演进构想：L0~L4 五层分离，先行冻结接口契约

**成果**：产出 4 份设计文档，已在个人仓库落地核心条款。
```
