## 方案构建意图简述

① 本方案面向看重工程交付与现场落地的岗位，最看重能否把方案做成可验收、可运维的系统，而非停在 demo。
② 本方案以电力监理 RPA、机场物流、广东交科三条横向证甲方交付与现场落地，以布控球证弱网边缘的现实适配，以光点、测绘院两段实习证大模型服务化与本地化交付——六条共同拼出从现场到系统的实干像。
③ 相比同届，形成「能扛现场交付、能落硬件与运维、段段有验收痕迹」的组合。

## 关键优势项目
- 关键项目1：
    需要突出的要点有：`已验收交付的定制软件全链路（JSON 配置化引擎 / 零代码 GUI / 内网免依赖部署）——工程实干主线：把报表规则变成甲方能用、能自行维护的系统；分支：交付实施岗看甲方内网落地与验收闭环，企业软件岗看可维护性设计（配置化与架构决策）`  
    示范内容如下：
```markdown
#### 南方电网广州电力工程监理有限公司 | 办公自动化 RPA 辅助软件开发项目 技术负责人 | 2024.10 - 2025.01
**相关技术栈**：Python / Pandas / openpyxl / PyQt5 / PyInstaller / COM 自动化

**项目背景**：电力监理业务中日报/周报等重复性报表完全依赖人工完成，每日耗时 1.5 小时且易出错。
**项目定位**：南方电网横向课题（已验收），担任技术负责人。

**核心工作**：
- 针对报表模板变更需改代码的痛点，设计「结构化 JSON 输出 + config 坐标映射驱动注入」两段式架构，把报表结构从代码剥离为配置，使模板变更零代码改动即可适配
- 针对甲方业务人员不具备技术能力的问题，搭建零代码可视化交互引擎（数据勾选 / 统计口径选择 / 督查反匹配全收敛到 GUI 与配置文件），业务人员不接触代码即可自助完成全流程
- 针对甲方 Windows 内网终端无 Python 环境的部署瓶颈，设计 PyInstaller 打包 + 全局日志捕获的交付链路，确保无依赖稳定运行

**成果**：每日 1.5 小时手工统计压缩至 3 分钟内，消除人工统计错漏。
```
- 关键项目2：
    需要突出的要点有：`IoT 硬件底座到现场运维的全栈实干（一期安检机硬件组装与电气负载校验 / 边缘设备五态机全生命周期管理 / 两期按期验收交付）——从硬件到服务器的现场落地证据；分支：系统集成/交付岗看现场部署与运维体系，硬件类公司看设备全链路`  
    示范内容如下：
```markdown
#### 机场物流集团 | 智慧物流系统迭代一/二期 | 项目总负责人（二期） | 2024.09 - 2026.09
**相关技术栈**：Spring Boot / Docker / MySQL / Redis / Prometheus / Grafana / IoT 架构

**项目背景**：机场转运库区依赖人工巡逻与事后录像回溯，违规行为发现滞后、取证难，无法满足多库区规模化实时监管需求。
**项目定位**：校企联合框架二期（合同 55 万 / 累计框架 90 万），本人任二期总负责人独立统筹全生命周期。

**核心工作**：
- 针对库区多场景违规识别需求，主导设计「边缘轻量推理 + 中央归档检索」多端协同分层架构，完成安检机硬件组装与电气负载校验（一期），落地 11 类违规 AI 视觉算法（二期）
- 针对组件间两两耦合导致扩展困难的问题，主导平台架构由 Spring Boot 分层 → 纵向分层 → 星形 Hub-Spoke 拓扑演进，配套二维数据分类治理与边缘设备五态机全生命周期管理
- 针对项目无运维保障体系的现状，搭建 Docker 容器化 B/S 部署与 Prometheus+Grafana 云边监控体系（15+ 告警），使 P1 故障恢复时间控制在 5 分钟以内、系统可用性达到 99.5%

**成果**：两期均按期通过验收并完成交付，为后续 AI 视觉技术在物流场景中的拓展应用奠定基础。
```
- 关键项目3：
    需要突出的要点有：`专用检测设备的端到端工程交付（双节点边缘架构 / gRPC 双向协议 / 4 路激光融合 / 端到端原型交付）——需求到实物的闭环落地；分支：工业检测/仪器公司看垂直场景落地，硬件岗看通信与传感器工程细节`  
    示范内容如下：
```markdown
#### 广东交科检测有限公司 | 钢筋直径与间距检测设备原型研发 技术负责人 | 2025.09 - 2026.09
**相关技术栈**：Python / Jetson Nano / OrangePi / gRPC / protobuf / UNet(ResNet50) / PySerial / OpenCV

**项目背景**：建筑施工现场钢筋直径与间距检测依赖人工卡尺抽检，效率低、覆盖率不足，且难以满足大规模施工的质检追溯需求。
**项目定位**：广东交科检测有限公司横向课题（合同 XX 万），本人任技术负责人，主导双节点边缘架构设计、算法部署与原型交付。

**核心工作**：
- 针对施工场景无 GPU 算力且需多传感器协同的瓶颈，设计 Jetson Nano（推理） + OrangePi（采集/换算）双节点边缘架构，以通信成本换故障域隔离，实现推理节点离线时自动降级至「仅视频+激光」基础模式
- 针对节点间状态同步与通信可靠性需求，设计 gRPC + protobuf 双向协议（独立 channel），配套帧同步算法与状态机（IDLE→INFERENCING→RETURNING），实现节点健康自诊断与异常自动恢复
- 针对 4 路激光测距传感器数据融合难题，打通串口通信全链路（帧解析 / 热插拔自动重连 / 融合策略动态切换），完成像素至物理尺寸映射换算，使直径测量值自动匹配 6~40mm 国标规格

**成果**：端到端原型已交付（POC 技术验证完成），实现直径与间距的自动测量与实时叠加显示。
```
- 关键项目4：
    需要突出的要点有：`弱网/无 GPU 边缘现场的适配与云台实体动作落地（海思 NPU 部署 / Lerp 平滑控制 / 端云协同折中架构）——真实作业现场的工程取舍；分支：边缘/安防硬件岗看国产平台适配，交付岗看受限现场下的方案权衡`  
    示范内容如下：
```markdown
#### 南网数字研究院/江门供电局 | 边缘布控球自适应目标检测与视频调控系统 技术总负责人 | 2024.06 - 2024.10
**相关技术栈**：Python / YOLOv8 / ByteTrack / 海思 NPU / PyTorch / 图像质量评估（Brenner / NR-IQA）

**项目背景**：电网施工布控球部署于弱网、边缘算力受限（海思 Hi3519DV500 NPU，无 GPU/CUDA）的作业现场，视频质量与目标跟踪效果难以保障。
**项目定位**：南方电网数字研究院纵向课题（后续立项为省级大创），任技术总负责人。

**核心工作**：
- 针对海思 NPU 边缘算力受限无法运行复杂评估模型的瓶颈，主笔《图像质量评估及优化方案》设计端云协同架构：边缘端以 Brenner/亮度指标初筛过滤明显异常，服务端以 Transformer NR-IQA 做精细化评估，平衡算力占用与评估精度
- 针对布控球在动态场景下目标易丢失的问题，独立编写 YOLOv8 + ByteTrack 视频跟踪测试脚本，设计基于 Lerp 线性插值与帧间平滑的云台自适应控制逻辑，输出实时 x/y 偏移与焦距缩放信号
- 针对电网场景缺乏客观图像融合评估基线的问题，构建 WireFO-MEF 多曝光数据集并制定清晰度主观打分规范，通过自动化测试脚本验证：边缘端客观评分召回/精准率达 70%+、服务端主客观一致率达 80%+

**成果**：相关成果获批省级大创立项，为国产边缘平台上的图像质量评估算法提供验证基线。
```
- 关键项目5：
    需要突出的要点有：`大模型服务的工程化落地（FastAPI 微服务拆分 / 本地 vLLM 与云端 API 混合调度 / Celery 异步编排）——把模型变成稳定在线服务的交付能力；分支：AI 应用交付岗看微服务与调度工程化，后端岗看异步编排与跨系统对接`  
    示范内容如下：
```markdown
#### 广州光点信息科技股份有限公司 | Python 开发实习生（AI 研发组） | 2025.03 - 2025.06
**相关技术栈**：Python / FastAPI / vLLM（Qwen2.5-14B、Llama 3） / Celery / Redis / 大模型 API

**项目背景**：企业全媒体热点运营依赖人工完成"监控-脚本-数媒合成"全链路，单条热点到视频产出需数小时，运营效率低。
**项目定位**：AI 研发组实习，负责微服务化架构与推理调度模块。

**核心工作**：
- 针对大模型能力与业务逻辑耦合导致的迭代效率低下问题，基于 FastAPI 将「要点提取/脚本二创」能力拆为独立微服务（标准化 REST 接口），使业务迭代与模型升级互不阻塞
- 针对全量调用云端 API 成本高、全量本地推理质量受限的三角困境，设计本地 vLLM（Qwen2.5-14B / Llama 3）处理常规任务 + 复杂创意路由云端 API 的混合调度策略
- 针对下游数字人系统跨团队交接的数据一致性问题，引入 Celery + Redis 异步队列并以标准化 JSON 协议对接脚本/时间轴/素材元数据，实现跨系统自动化流转

**成果**：单条热点到视频产出从人工数小时压缩至 15 分钟内。
```
- 关键项目6：
    需要突出的要点有：`数据不出域约束下的本地化系统交付（微内核六层架构 / BERT 意图路由与三级权限 / 需求期望管理）——合规现场的端到端交付与文档链；分支：政企交付岗看本地化与需求管理，架构岗看微内核可替换设计`

```markdown
#### 广东省国土资源测绘院 | 系统开发实习生（卫星应用中心） | 2025.07 - 2025.10
**相关技术栈**：Python / FastAPI / Milvus / vLLM（Qwen3） / BERT / Docker / Nginx / LangChain / RAG

**项目背景**：测绘院 PB 级非结构化专业文档与地理空间数据长期分散存储，依赖人工检索且受"数据不出域"合规约束，效率低下。
**项目定位**：实习项目，主导 RAG 系统核心架构与本地化部署全链路交付。

**核心工作**：
- 针对数据分散且不能出域的合规约束，设计「逻辑核心 + 功能插件」微内核 + 六层分层架构，使检索链路各环节可独立替换而不触动核心，满足模块化迭代要求
- 针对内部/外部查询的数据隔离需求，基于 BERT 微调实现意图二分类路由（内部走本地库、外部经安全通道受控访问），配套三级权限治理，确保数据不出内网
- 针对项目初期甲方对大模型期望过高的问题，通过多轮需求调研与早期 Demo 量化评估数据管理期望，将项目目标从「开放式通用问答」收敛至「精准检索与故障排查」，规避范围蔓延

**成果**：专业问答忠实度≥95% / 相关率≥90%，交付需求/技术方案/测试/工作总结完整文档链。
```
