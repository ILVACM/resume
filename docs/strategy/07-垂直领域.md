## 适用领域分组

垂直领域

## 方案构建意图简述

① 领域专用软件方向最看重"能否做出真正落地到垂直行业的专用软件，打通需求到交付的闭环"。
② 本方案选「交科检测设备（技术负责人，撑专用设备软件全链路与 Agent 规约前置）+ 测绘院知识库（撑知识工程与权限治理）+ 电力监理 RPA（撑业务 SOP 软件化）+ 嵌入式竞赛（撑软硬件结合基础）」四条为骨架。
③ 与同届相比，形成"能啃垂直领域硬骨头 + 有架构权衡与工程治理 + 软硬结合"的组合，而非只做过通用网页应用。

## 关键优势项目
- 关键项目1：
    需要突出的要点有：`垂直行业大型系统全生命周期交付——项目总负责人独立统筹立项到验收；分支：行业软件公司看垂直场景闭环交付，项目管理岗看统筹与商业交付`  
    示范内容如下：
```markdown
#### 机场物流集团 | 智慧物流系统迭代二期 项目总负责人 | 2025.07 - 2026.09
**相关技术栈**：DeepSORT / MediaPipe / ST-GCN / Spring Boot / Docker / Prometheus / Grafana / 边缘推理

**项目背景**：机场转运库区依赖人工巡逻与事后录像回溯，违规行为发现滞后、取证难，无法满足多库区规模化实时监管需求。
**项目定位**：校企联合框架二期（合同 55 万 / 累计框架 90 万），本人任二期总负责人独立统筹全生命周期。

**核心工作**：
- 针对库区多场景违规识别需求，主导开发 11 类违规行为 AI 视觉算法（DeepSORT 运动轨迹 + MediaPipe / ST-GCN 时空图卷积），覆盖车辆超速、人员离岗、晕倒摔倒等场景
- 针对组件间两两耦合导致扩展困难的问题，主导平台架构由 Spring Boot 分层 → 纵向分层 → 星形 Hub-Spoke 拓扑演进，使新增业务组件仅需对接中枢单一契约
- 针对项目无运维保障体系的现状，搭建 Docker 容器化 B/S 部署与 Prometheus+Grafana 云边监控体系（15+ 告警），将 P1 故障恢复时间压缩至 5 分钟内、系统可用性提升至 99.5%

**成果**：按期高质量验收交付，甲方委托横向拓展二期。
```
- 关键项目2：
    需要突出的要点有：`专用检测设备软件全链路（需求→算法→硬件→实测）——"领域专用"的完整叙事；分支：工业软件/检测仪器公司看垂直场景闭环能力`  
    示范内容如下：
```markdown
#### 广东交科检测有限公司 | 钢筋直径与间距检测设备原型研发 技术负责人 | 2025.09 - 2026.09
**相关技术栈**：Python / Jetson Nano / OrangePi / gRPC / protobuf / UNet(ResNet50) / PySerial / OpenCV

**项目背景**：建筑施工现场钢筋直径与间距检测依赖人工卡尺抽检，效率低、覆盖率不足，且难以满足大规模施工的质检追溯需求。
**项目定位**：广东交科检测有限公司横向课题（合同 XX 万），本人任技术负责人，主导双节点边缘架构设计、算法部署与原型交付。

**核心工作**：
- 针对施工场景无 GPU 算力且需多传感器协同的瓶颈，设计 Jetson Nano（推理） + OrangePi（采集/换算）双节点边缘架构，以通信成本换故障域隔离，实现推理节点离线时自动降级至「仅视频+激光」基础模式
- 针对节点间状态同步与通信可靠性需求，设计 gRPC + protobuf 双向协议（独立 channel），配套帧同步算法与状态机（IDLE→INFERENCING→RETURNING），实现节点健康自诊断与异常自动恢复
- 针对 4 路激光测距传感器数据融合难题，打通串口通信全链路（帧解析 / 热插拔自动重连 / 融合策略动态切换），完成像素至物理尺寸映射换算，使直径测量值自动匹配 6~40mm 国标规格

**成果**：端到端原型已交付（POC 技术验证完成），实现直径与间距的自动测量与实时叠加显示。
```
- 关键项目3：
    需要突出的要点有：`测绘/GIS 领域专用知识库——垂直领域知识工程经验；分支：南方数码等测绘/GIS 公司直接对口，其他领域公司看知识工程方法论迁移`  
    示范内容如下：
```markdown
#### 广东省国土资源测绘院 | 系统开发实习生（卫星应用中心） | 2025.07 - 2025.10
**相关技术栈**：Python / FastAPI / Milvus / vLLM（Qwen3） / BERT / Docker / Nginx / LangChain / RAG

**项目背景**：测绘院 PB 级非结构化专业文档与地理空间数据长期分散存储，依赖人工检索且受"数据不出域"合规约束，效率低下。
**项目定位**：实习项目，主导 RAG 系统核心架构与本地化部署全链路交付。

**核心工作**：
- 针对数据分散且不能出域的合规约束，设计「逻辑核心 + 功能插件」微内核 + 六层分层架构，使检索链路各环节可独立替换而不触动核心，满足模块化迭代要求
- 针对内部/外部查询的数据隔离需求，基于 BERT 微调实现意图二分类路由（内部走本地库、外部经安全通道受控访问），配套三级权限治理，确保数据不出内网
- 针对项目初期甲方对大模型期望过高的问题，通过多轮需求调研与早期 Demo 量化评估数据管理期望，将项目目标从「开放式通用问答」收敛至「精准检索与故障排查」，规避范围蔓延

**成果**：专业问答忠实度≥95% / 相关率≥90%，交付需求/技术方案/测试/工作总结完整文档链。
```
- 关键项目4：
    需要突出的要点有：`电力监理领域专用 RPA 工具——垂直业务 SOP 的软件化样板；分支：垂直领域软件公司看业务抽象与配置化设计`  
    示范内容如下：
```markdown
#### 南方电网广州电力工程监理有限公司 | 办公自动化 RPA 辅助软件开发项目 技术负责人 | 2024.10 - 2025.01
**相关技术栈**：Python / Pandas / openpyxl / PyQt5 / PyInstaller / COM 自动化

**项目背景**：电力监理业务中日报/周报等重复性报表完全依赖人工完成，每日耗时 1.5 小时且易出错。
**项目定位**：南方电网横向课题（已验收），担任技术负责人。

**核心工作**：
- 针对报表模板变更需改代码的痛点，设计「结构化 JSON 输出 + config 坐标映射驱动注入」两段式架构，把报表结构从代码剥离为配置，使模板变更零代码改动即可适配
- 针对甲方业务人员不具备技术能力的问题，搭建零代码可视化交互引擎（数据勾选 / 统计口径选择 / 督查反匹配全收敛到 GUI 与配置文件），业务人员不接触代码即可自助完成全流程
- 针对甲方 Windows 内网终端无 Python 环境的部署瓶颈，设计 PyInstaller 打包 + 全局日志捕获的交付链路，确保无依赖稳定运行

**成果**：每日 1.5 小时手工统计压缩至 3 分钟内，消除人工统计错漏。
```
