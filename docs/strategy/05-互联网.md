## 适用领域分组

互联网

## 方案构建意图简述

① 本组为有核心自有产品业务的公司集团（纯 AI 公司归「agent」）；最看重完整项目从立项到上线的交付能力与算法底子。
② 本方案选「机场物流（总负责人，撑全生命周期交付与统筹）+ 光点短视频（撑微服务解耦与推理调度）+ 测绘院知识库（撑 PB 级数据处理与权限治理）+ 算法竞赛（撑算法硬实力）」四条为骨架。
③ 与同届相比，形成"能独立扛交付 + 有规模化数据处理 + 算法有硬背书"的组合，而非只写过业务代码。

## 关键优势项目
- 关键项目1：
    需要突出的要点有：`90 万合同项目总负责人 + 全生命周期交付；系统架构演进（Hub-Spoke 通信中枢）与架构治理（二维数据分类 / 边缘设备五态机）——大厂看工程成熟度、责任与协作；分支：业务后端/客户端岗看交付与统筹，基础架构岗看架构演进与云边监控体系`  
    示范内容如下：
```markdown
#### 机场物流集团 | 智慧物流系统迭代二期 项目总负责人 | 2025.07 - 2026.09

**项目概述**：合同 55 万的库区 AI 监控系统（校企联合框架累计 90 万），本人作为总负责人独立统筹全生命周期。

**核心工作**：
- 独立主导全生命周期：业务调研 → 合同拟定 → 立项 → 架构设计 → 验收交付
- 多端协同与场景化分层：按场景设计分层技术架构（感知→时空建模→轨迹决策→响应中枢→系统赋能），落地边缘推理 + 中央归档检索协同
- 系统架构演进（决策链）：由 Spring Boot 分层 → SOP 纵向业务分层 → 星形 Hub-Spoke 通信中枢，以中枢为代价换取组件对中枢的单一契约；配套二维数据分类治理与边缘设备五态机全生命周期管理
- 主导多场景 AI 视觉算法攻坚与国产边缘算力部署，保障项目按期高质量交付
- 建立 Docker 容器化部署与云边监控体系（Prometheus+Grafana，15+ 告警），可用性 99.5%

**成果**：按期高质量验收，获甲方高层认可。
```
- 关键项目2：
    需要突出的要点有：`微服务解耦 + 异步任务编排 + 混合推理调度——互联网工程风格的标准化设计；分支：后端/平台岗看服务化与队列设计，AI 应用岗看推理调度`  
    示范内容如下：
```markdown
#### 广州光点信息科技股份有限公司 | Python 开发实习生（AI 研发组） | 2025.03 - 2025.06

**项目概述**：全媒体热点追踪与 AI 自动化短视频生成矩阵系统，从 0 到 1 打通"监控-生成-合成"全链路。

**核心工作**：
- 服务化架构设计：基于 FastAPI 按职责边界把大模型能力拆为独立微服务（要点提取 / 脚本二创），对外只暴露标准接口，模型迭代与业务迭代解耦
- 跨系统协作契约：引入 Celery + Redis 异步任务队列解耦下载与推理流程，以标准化 JSON 数据交换协议与下游数字人系统交接脚本/时间轴/素材元数据，把跨部门对接成本固化为一次性接口约定
- 云边混合推理调度与成本/时延/质量三角权衡：常规任务走本地 vLLM（成本与数据可控），复杂创意动态路由云端 API（质量优先），含 API Key 池轮询与指数退避重试
- 基于 UI 自动化实现多平台反爬采集与数据清洗

**成果**：单条热点到视频产出从人工数小时压缩至 15 分钟内。
```
- 关键项目3：
    需要突出的要点有：`PB 级数据 + 微内核六层架构（检索环节可独立替换）+ 千万级向量存储——大规模数据处理与系统架构设计能力；分支：数据/存储方向看流水线与向量库，算法方向看检索增强，架构岗看微内核与可替换性设计`  
    示范内容如下：
```markdown
#### 广东省国土资源测绘院 | 系统开发实习生（卫星应用中心） | 2025.07 - 2025.10

**项目概述**：GDCORS 智能知识库与政企本地化 RAG 问答系统，支撑 PB 级地理空间业务数据场景。

**核心工作**：
- 主导分布式文档解析流水线：集成 OCR 与版面分析，多源资料清洗分块（Chunking）入 Milvus，以异步任务队列处理海量数据
- 系统架构设计：采用「逻辑核心 + 功能插件」微内核 + 六层分层，插件标准接口挂载向量库 / 模型 / 意图识别，检索各环节可独立替换而不触动逻辑核心
- 数据隔离分流与权限治理：BERT 微调意图二分类路由，内部分支走本地库（数据不出内网）、外部经安全通道受控访问；员工/项目经理/管理员三级权限
- 实现千万级文档块在 Milvus 的高效存储与检索
- 设计意图识别路由 + HyDE + 多路召回 + BGE-Reranker 重排序

**成果**：忠实度≥95%/相关率≥90%；数据"不出域"合规、内网稳定运行。
```
- 关键项目4：
    需要突出的要点有：`Agent 规约体系构想设计——工程规范与可追溯治理能力；分支：大厂看工程治理体系与 Git 追踪机制，平台 / 基础架构岗看规约与契约意识`  
    示范内容如下：
```markdown
#### Agent 规约体系构想设计 | 个人思考实践 | 2026.08 - 至今

**项目概述**：面向多 Agent 协作的工程规约体系（提示词工程 → harness 中间态）——由「直接向 agent 下达任务不可靠」出发自主立项。

**核心工作**：
- 体系架构设计：约束层 / 知识层 / 实例层三层逻辑，约束力逐级递减；落地为根目录 `AGENTS.md` 与 `.spec/` 双载体
- 机制设计：任务执行锚点机制（规定层 / 锚点层 / 详情层追踪）；Git 追踪（锚点 ↔ commit hash 绑定、路径限定提交、提交消息模板）
- 工程判断与风险处置：主动校正三处前提偏差（同账户只读 ≠ 安全边界 / SQLite 不防内容幻觉 / 二进制入库破坏 diff）；保留降级模式
- harness 化演进规划：L0 条款 / L1 契约 / L2 实现 / L3 状态 / L4 证据五层分离；规划 validate / check / anchor / render / hash 五类 CLI

**成果**：产出 4 份设计文档并已落地运行。
```
