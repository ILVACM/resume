## 2. 子版本简历实例台账

基于模板 `Resume-Lite.md` 复制、内容取自母版 `Resume.md` 定制的**全部实例**（`Resume-{目标}-{版本}-base.md`）。  
**只登记 markdown 源文件**；由实例构建的 PDF 产物不入账——PDF 可随时从 md 重建，版本追溯由 tag 承担（规范见 [`tag.md`](tag.md)、日志见 [`TargetCompanies.md`](TargetCompanies.md)）。  
「目标指向」为该实例的定制方向：可以是某一家具体公司，也可以是某一类公司或分组（参照 [`TargetCompanies.md`](TargetCompanies.md) 分组）。  
定制流程见 [`strategy.md`](strategy.md)。    

| 文件 | 登记日期 | 目标指向 | 状态 | 对应 tag |
|---|---|---|---|---|
| _（暂无实例；每定制一份立即登记一行）_ | | | | |

状态取值：`active`（当前可投）/ `archive`（内容过期，文件保留）。
「文件」列填当前最新版本的实例命名 `Resume-{目标}-{版本}-base.md`；版本迭代产生新文件时更新本列，旧版本由 git 历史保留。
「对应 tag」记录该实例**最新一次**投递的 tag；同一实例多次投递的完整历史见 [`TargetCompanies.md`](TargetCompanies.md) 投递日志。

转换规则：当某实例内容已过期（如对应分组方案大改、或母版经历重大更新且长期未投），将其「状态」由 active 改为 archive；文件保留、git 历史可追溯，新投递须基于新版本实例（阶段 A 重新构建）。

## 维护说明

- 新项目先归档资料到 `docs/{横向|纵向|实习|竞赛}/{项目简称}/`（同组多项目建议加序号前缀区分），再在 §1 登记，最后更新母版 `Resume.md`（索引先行原则，详见 [`AGENTS.md`](../AGENTS.md) §4.1）。
- §1「相关领域」用语与 [`TargetCompanies.md`](TargetCompanies.md) 的公司性质分组**保持一致**（按关联度降序、1~3 个），设计简历编写策略时以此为键检索匹配。
- §1 条目应与 `Resume.md` 保持一致，增删时同步两处。
- 资料索引为"待补充"的条目，补齐路径后请同步更新本表并删除"待补充资料路径"备注。
- 简历实例定制完成后**立即**在 §2 登记（流程见 [`strategy.md`](strategy.md)）；投递 tag 规范见 [`tag.md`](tag.md)，日志见 [`TargetCompanies.md`](TargetCompanies.md)。
