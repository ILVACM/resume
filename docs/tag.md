# tag.md — 投递 tag 规范

> **定位**：投递 tag 的格式、铁律与用法的唯一权威文档。
> **分工**：tag 的台账以 [`TargetCompanies.md`](TargetCompanies.md)「投递日志」的「对应 tag」列承载（与日志同表，单一事实来源，不另设独立台账表）；实例登记见 [`INDEX.md`](INDEX.md) §2；定制流程见 [`strategy.md`](strategy.md)。

## 这是什么

**tag 是你每次投递那一刻的"快照封条"。** 简历会不断修改，但投出去的那一份必须定格——tag 把那一刻的文件状态钉死，之后无论再怎么改简历，都能随时精确还原"当时投的到底是哪一版"。配合 TargetCompanies 的投递日志，任何一次投递都能回答三个问题：**投的哪版、投给谁、哪天投的**。

## 两种 tag

| 类型 | 长什么样 | 什么时候打 | 通俗理解 |
|---|---|---|---|
| 基线 tag | `v1.0-base` | 母版改稳定了就打一个 | "定稿存档点"——这版是可靠基准；内容有实质修改升版本号（`v1.0` → `v1.1`），只改错字不用升 |
| 投递快照 tag | `v1.1-ByteDance-20260905` | **每次投递前必打** | 名字即信息——第 1.1 版简历、投给字节、2026-09-05 投的 |

快照 tag 的粒度是**投递事件**：「投递公司名称」写实际投递的公司名——即使实例的目标指向是一类公司。tag 与投递副本文件名的**版本 / 公司 / 日期三要素一致**：如实例 `Resume-金融科技-v1.0-base.md` 投招银网络，投递副本为 `Resume-金融科技-v1.0-招银网络-20260910.md`，tag 即 `v1.0-招银网络-20260910`（命名规范详见 [`strategy.md`](strategy.md)）。

## 三条铁律

1. 每次投递**必须先打 tag 再投**，并在 TargetCompanies 的投递日志追加一行——没有 tag 的投递，日后无法证明投的是哪一版。
2. **tag 打了就不删、不改名**——历史不可篡改，背调、复盘、面试回忆时才可信。
3. **同一公司再投就是新 tag**（日期不同即新建）——两次投递的简历版本可能不一样，不能混用同一个封条。同日同公司多次投递，在日期后追加序号后缀 `-N`（如 `v1.0-招银网络-20260910-2`），投递日志「日期」列记 `20260910-2`；tag 全局唯一，重名即报错，绝不覆盖既有 tag。

## 怎么配合使用

1. **投递前**：打快照 tag → [`TargetCompanies.md`](TargetCompanies.md) 的**投递日志**追加一行（日期 / 简历文件 / 目标公司 / 对应 tag）。
2. **投递后**：更新公司清单中该公司的「投递简历 / 状态」列为**最新**进展——状态取值如 `投递中`、`一面`、`二面`、`offer`、`挂`。

> 一句话分工：**公司表看现状，日志看全过程，tag 保证每一版都能还原。**
