我 2023 年入学读本科，一开学正好赶上 OpenAI 通过 GPT 让 LLM 第一次火爆出圈。可以说我最开始就注意到了 AI，一直尝试把它引入自己的工作流：从提示词工程，到上下文管理，再到现在的 harness 设计，持续摸索一套完全适合我个人的 agent 协作体系。我所有的项目——甚至课设和大实验——都有 agent 协作的影响。

底子是这么打起来的：大一上入选校 ACM 算法集训队（校内第 19 名），之后进「华为—昇腾」创享社的嵌入式方向，大一下进广工广东省物理信息融合实验室，跟着黄国恒副教授做项目。这几步给我两样东西：还算扎实的算法底子，和“代码最终要落在设备和现场上”的意识。

真正让我长本事的是这几段校企合作项目，走的是一条从参与到负责、再到主导的线。

最早是南方电网广州电力工程监理的办公自动化 RPA（10 万，技术负责人，已验收交付）。做的是“把业务规则变成程序”：把甲方报表里筛选、分列、多条件嵌套统计的口径抽象为可复用 Pandas 函数库；更关键的是把报表结构从代码里剥出来，改成结构化 JSON 加配置映射注入 Excel——模板再变，只改配置、不动代码。交付时打成免安装程序，甲方没装 Python 的 Windows 内网机上直接能跑。原本每天 1.5 小时的手工统计压到 3 分钟以内。

后来是广东交科检测的钢筋直径与间距检测设备（25 万，技术负责人）。要解决“在设备上跑得稳”：推理、采集、渲染和串口在单板上互抢资源，我把 AI 推理和系统调度物理隔成两个节点——Jetson Nano 专跑 UNet 分割、OrangePi 负责采集、激光解析和界面；代价是多一层通信，换回来的是资源不抢、故障域隔离、推理节点可独立换型。还打通 4 路激光链路、做像素到尺寸的换算，并把帧同步、心跳降级和参数配置化收成「协议冻结—状态机—自动降级」的闭环，让设备在无人值守时也能自证状态、安全退化。

再往后是机场物流集团智慧物流系统二期（55 万，校企联合框架累计 90 万）。这次我是项目总负责人，独立统筹业务调研、合同拟定、架构设计到验收交付，并主导库区 11 类违规行为的算法开发。最硬的是国产边缘算力适配——把模型转到北京灵汐 HS100-L 类脑芯片上，用 LynSDK 重写推理管线，单路视频延迟压进 200ms。系统侧也从 Spring Boot 分层按业务 SOP 重组成纵向分层，最后收敛成以通信中枢为中心的星形拓扑，组件不再两两直连；部署上做 Docker 容器化，配云边监控的 15 条以上告警，P1 故障恢复控制在 5 分钟内、可用性 99.5%，并按 100TB 视频归档与亿级事件检索的设计要求规划存储与检索。

中间还夹着两段实习：在光点信息科技负责反爬采集链路、本地双 STT 引擎的部署与路由，并把大模型能力剥离成 FastAPI 微服务；在广东省国土资源测绘院，用微内核加六层分层配合意图路由和三级权限，在数据“绝对不出域”的前提下把一套本地化 RAG 问答系统从 0 做到 1，专业问答忠实度 95% 以上、相关率 90% 以上。

这些项目我几乎都是和 AI 一起做的，选型和分工也想得比较清楚。工具上长期用本地 Agent 类工具（Trae、opencode、mimocode 等），当时它们有近乎不限量的免费额度，适合长周期、高频改动的开发；模型分场景用——日常开发与文档处理走国产模型（中文与性价比最划算），需要更强推理时再切更强的那一档。分工上，需求与期望管理、系统总体设计、评估与验收标准我定；规范化、重复性的实现交给 AI。我坚持“约束前置”：把约定写进一份规则文件，让 AI 开工先读它、再按需加载下游文档，而不是靠我一遍遍口头叮嘱。

做久了，我发现自己更在意的不是“把功能写出来”，而是“怎么把事情设计对”。一层是系统架构：报表结构要不要从代码里剥离、推理和调度要不要分两个节点、检索链路要不要做成可插拔微内核、组件之间要不要收敛到一个中枢——每选一次，系统后面的可维护性和生命周期就跟着变。一层是系统工程：硬件装得上、集群稳得住、模型跑得动、数据既要出不去又要查得到，还得经得起长期运维，这些是同一件事的不同侧面，得放在一起设计。一层是工程设计：把目标收敛住（比如把“开放式通用问答”收敛到“精准检索与故障排查”），再用 LLM-as-a-Judge 这类量化闭环把“好不好”变成可比较的指标。最后是 agent 规约与 harness：上面那套“约束前置”后来扩展成了我自己的 agent 规约体系，现在正规划向可执行的 harness 演进。

另外，技术负责人和总负责人我都做过，习惯在甲方、导师、跨部门之间收敛目标、推动决策——既沉得下去写代码，也站得出来对外沟通。
