我 2023 年入学读本科，一开学正好赶上 OpenAI 通过 GPT 让 LLM 第一次火爆出圈。可以说我最开始就注意到了 AI，一直尝试把它引入自己的工作流：从提示词工程，到上下文管理，再到现在的 harness 设计，持续摸索一套完全适合我个人的 agent 协作体系。我所有的项目——甚至课设和大实验——都有 agent 协作的影响。下面是较有代表性的一个经历。
一、目标与背景：广东省国土资源测绘院卫星应用中心实习，为院内做本地化 GDCORS 智能知识库与 RAG 问答系统。院里有操作手册、测绘规范、扫描图纸等非结构化文档与 PB 级地理空间数据，查规范、找故障只能人工翻阅；又受“绝对不出域”约束，不能用公有大模型；任务是在内网把它从 0 做到 1。
二、AI 工具与模型（及选择原因）：主力用 Trae、opencode、mimocode——当时三者都近乎不限量免费，正好适合长周期高频改动。模型分两类：日常开发用 Qwen3.7-Plus、GLM-5.1、GLM-5.2、kimi-k2.7，国内模型在中文与性价比上最划算；要更强推理，趁 VPN 可用切 gpt5.5。
三、我与 AI 的分工：需求与期望管理（把目标从“开放式通用问答”收敛到“精准检索与故障排查”）、系统总体设计、评估与验收标准都由我定；AI 做规范化的重复实现——代码、脚本与文档。我坚持“约束前置”：把约定写进一份规则文件，让 AI 开工先读它、再按需加载下游文档；这套做法后来扩展成了我自己的 agent 规约体系，并规划向可执行的 harness 演进。
四、核心挑战与解决方案：① 系统工程层面的硬约束——数据绝对不出域、本地算力有限，还要过院信息中心：我争取到本地算力、用 vLLM 量化部署开源模型，让“内部资料走本地库、外部信息经安全通道”的意图路由兜住合规。② 架构必须能演进——模型、向量库、意图识别都会换：我用「逻辑核心 + 功能插件」微内核加六层分层，把三者按标准接口挂到插件层，使各环节可独立替换而不触动核心。③ AI 产出不可控——输出不稳、易幻觉：搭起 LLM-as-a-Judge 评估体系，按相关性、准确性、幻觉率三维量化，反哺 Prompt 与切分。
五、项目结果：系统在内网稳定交付运行，专业问答忠实度 ≥95%、相关率 ≥90%，并交付需求、方案、测试、总结文档。
