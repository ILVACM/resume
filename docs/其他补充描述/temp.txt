截止到目前，我有两段实习经历。

两段实习刚好串联了我对"AI 怎么变成真正有用的东西"这件事的理解过程。在光点那段主要是在试——把大模型从业务流里拆出来当独立服务跑，试着在本地推理和云端 API 之间找最优调度方案，算是第一次把课本上"微服务"的概念用在了 AI 上。到了测绘院就不是试了，是实打实要交付——从需求调研到架构搭起来，从数据处理流水线到本地化部署全部要落地，甲方等着用、数据不能出、算力还有限，所有工程权衡都得当场做决定。两个加在一起，刚好覆盖了从"能跑"到"能用"再到"好用"的完整体感。

两段实习做的事情其实是一脉相承的——都是把大模型的能力从"能跑通的 demo"变成"真正能用的工程系统"。在光点信息那边主要是做 LLM 的微服务化拆分，把大模型能力从业务流里剥离出来，封装成独立服务，然后在本地 vLLM 和云端 API 之间做混合推理调度，本质上就是在成本、时延和质量之间找最优解。后面到测绘院实习，做的事情更完整了——从需求调研开始，到 RAG 系统的微内核架构设计，到 PB 级文档的解析与向量化流水线，再到意图路由、多路召回、Reranker 重排序这一整套检索增强链路，全部从 0 到 1 搭起来，最后还要在本地算力服务器上部署，满足数据不能出域的合规要求。两段加起来的感觉就是，不只是会调模型做推理，更清楚怎么把模型能力打包成可靠的产品，怎么在真实约束下面做工程权衡。

回头看这些项目，自己一直在练的其实是一套工程实现的完整能力——不是纯搞研究、也不是简单地写代码，而是怎么把一个需求从纸面变成真正能跑的系统，最终交付到甲方手里。RPA 项目是第一次接触真实交付，真正难的不是算法，是设计一个配置化引擎让甲方自己改模板就能用，不用每次都找开发。机场物流项目是真正的考验，五十多万的项目从调研到验收全流程自己扛，边防国产类脑芯片适配边调推理管线，边搞云边监控边应付甲方改需求——这时候才真正理解什么叫系统工程管理，技术只占一部分，更多时候是在做统筹决策、资源调度和风险控制。交科那个双节点项目是在用架构换可靠性，把推理和采集物理拆成两个节点，用 gRPC 通信跑通整条数据链路。纵向那边，南网布控球是端云协同跟踪算法加图像质量评估，省基金是做多智能体医学报告生成，这两条偏理论一些，但也得把科研想法工程化跑通才算数。

5 个项目串在一起，核心打的是工程能力这块地基——项目管理、架构决策、系统交付、风险控制这一整套实际工程经验。亮点有三个：一是 agent 方向，从提示词工程到上下文管理再到现在的 harness 设计，自己摸索出一套人机协作的工程范式，往深了做有省基金多智能体研究，往实了做有测绘院 RAG 落地；二是系统集成工程这块，机场物流和交科都是典型的物联网系统集成项目，从边缘硬件到云边通信到平台架构全链路都做过，甲方给的五十多万项目能独立扛下并交付就是证明；三是实践宽度够，既有横向三条已经落地交付的项目（累计一百多万合同金额），也有纵向两条在科研深度上做探索，还有 RPA 这种已经验收跑在甲方日常业务里的。对本科生来说，能把系统从立项推到验收、从纸面推到生产，这套工程能力本身就是最有说服力的。
